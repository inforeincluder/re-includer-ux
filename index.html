O processo

Da inspeção ao trabalho profissional

01

Informe uma URL

Indique uma página pública. A inspeção percorre páginas do mesmo domínio dentro de limites definidos.

02

Organize evidências

A ferramenta coleta estrutura, conteúdo, navegação e sinais técnicos observáveis, sem interagir com controles.

03

Valide e priorize

Use o relatório como base para investigar hipóteses, avaliar impacto e decidir o que merece validação humana.

Transparência e limites

Um ponto de partida, não um veredito.

A inspeção é pública, limitada e não invasiva. Não autentica, não clica em controles, não envia formulários e não altera dados. Não substitui pesquisa com usuários, avaliação contextual de UX, análise de negócio ou auditorias técnicas especializadas.

A URL informada e os dados públicos coletados são processados pelo workflow do GitHub Actions e enviados à API do Gemini para gerar o relatório. A chave de API é mantida como segredo do GitHub; isso não significa que o conteúdo analisado permaneça apenas no navegador.

O relatório deve distinguir fatos observados, interpretações, hipóteses e itens não verificados. A avaliação, priorização e decisão final cabem ao profissional responsável.
